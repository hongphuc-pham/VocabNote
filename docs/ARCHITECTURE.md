# Architecture

## 1. Shape of the system

There is no server. The app is a **single Flutter client with a local SQLite database**, plus
two optional outbound calls (dictionary lookup, opening a URL). That constraint drives
everything below.

```
┌──────────────────────────── Device ─────────────────────────────┐
│                                                                 │
│  Presentation      screens/ widgets/  (Flutter, Material 3)     │
│        │  watches providers                                     │
│  Application       controllers, services, game engines          │
│        │  depends on interfaces only                            │
│  Domain            entities, value objects, repository contracts│
│        ▲  implemented by                                        │
│  Data              Drift DAOs · TTS adapter · dictionary client │
│        │                                                        │
│  ┌─────┴──────┐   ┌──────────────┐   ┌──────────────────────┐   │
│  │ SQLite     │   │ OS TTS engine│   │ assets/cmudict-ipa   │   │
│  │ (Drift)    │   │ (flutter_tts)│   │ (offline fallback)   │   │
│  └────────────┘   └──────────────┘   └──────────────────────┘   │
└──────────────────────────────┬──────────────────────────────────┘
                               │ optional, user-triggered
                  ┌────────────┴────────────┐
                  │ freedictionaryapi.com   │  (look-up only)
                  │ dictionary.cambridge.org│  (opened in browser)
                  └─────────────────────────┘
```

**Dependency rule:** presentation → application → domain ← data. Domain imports nothing but
Dart, `meta` and `freezed`. Data never imports presentation. Any violation fails
`test/architecture/layer_boundaries_test.dart` — see §3.2 for why that is a test and not a
lint, and for the one documented exception.

### 3.1 Deviations from the original list, and why *(decided at M0)*

| Package | Decision | Reason |
|---|---|---|
| `riverpod_lint` | **not installed** | It requires `custom_lint`, which pins `analyzer ^8`, while `drift_dev` requires `analyzer >=13`. The two cannot coexist. Drift is ADR-001 and not negotiable, so the lint is dropped until `custom_lint` catches up. Re-check at each milestone. |
| Riverpod **2** → **3** | **Riverpod 3** | Riverpod 2 with codegen is not installable alongside Drift: `riverpod_generator` 2.x needs `source_gen ^2`, `drift_dev` needs `source_gen >=3`. Riverpod 2.6.1 is also 22 months old and unmaintained, failing `RULES.md` §17. |
| `sqlite3_flutter_libs` | **not a direct dependency** | Since `0.6.0+eol` the package is an empty stub — `package:sqlite3` 3.x bundles the native libraries itself. It still arrives transitively via `drift_flutter`; listing it directly would advertise a dependency that does nothing. |
| `meta` | **added** | `@immutable` in `domain/`, which may not import Flutter (§1). BSD-3, Dart team. |
| `dynamic_color` | **not added, and no hand-written equivalent either** | Originally skipped because Material You needs one integer from one platform channel and `RULES.md` §18 prefers a helper. The helper existed until the M3 restyle and was then deleted with it: the device accent *replaced* the brand seed, so on Android 12+ most users would never have seen the app's own colours. See `UI-UX.md` §2. |

### 3.3 The DI seam between application and data *(decided at M2)*

§1 says application "depends on interfaces only", and §20 of `RULES.md` forbids the import
that would otherwise be needed to reach a Riverpod provider constructing a repository. So:

- `application/repositories.dart` **declares** every repository provider, typed against its
  `domain/` interface, throwing `UnimplementedError` by default;
- `data/composition_root.dart` **supplies** the implementations as a list of overrides;
- `bootstrap.dart` applies them. Tests call the same function against an in-memory database,
  so there is one list rather than two that drift apart.

`data/composition_root.dart` is the third and final entry on the composition-root exemption
list in `test/architecture/layer_boundaries_test.dart`. The test is what forced this
structure — the first draft had `application → data` and `presentation → data`, and it
failed the build, which is exactly what it is for.

### 3.2 Enforcing the layer direction *(decided at M0)*

With `custom_lint` unavailable, the dependency rule in §1 is enforced by
`test/architecture/layer_boundaries_test.dart`, which fails the build on a
violation exactly as a lint would. It also checks that `domain/` imports nothing
but Dart, `meta` and `freezed`, and that only `core/extensions/grapheme.dart`
touches `package:characters` (ADR-006).

**One documented exception.** §2 places the router in `core/router/`, but a
router must name screens, and §1 forbids `core → presentation`. Both rules
cannot hold for that one file, so `core/router/app_router.dart` and
`bootstrap.dart` are exempt *by name* as composition roots — the places where
wiring is supposed to cross layers. Nothing else under `core/` may import
`presentation/`, and that is separately tested. If a third file wants the
exemption, the answer is an interface, not a longer list.

## 4. Cross-cutting decisions

**ADR-001 — Drift over Isar/Hive.** The hard requirement is "a new app version must adopt the
existing database". Drift gives numbered schema versions, generated step-by-step migrations
and *testable* migrations against exported schema snapshots. Isar/Hive push schema evolution
into runtime guesswork. See `docs/DATABASE.md`.

**ADR-002 — Riverpod over BLoC.** Small app, many small pieces of derived state (due counts,
search results, filter chips). Riverpod's `select`/`family` avoids the boilerplate of an event
class per interaction, and providers can be overridden in tests with fakes.

**ADR-003 — TTS instead of downloaded audio.** Chosen for v1: offline, zero storage, no
licence obligations, every word works (including nonsense words and names). Trade-off: it is a
synthesised reference, not a native speaker. Mitigation: the audio layer is behind
`SpeechService`, so a future `RemoteAudioService` (Wiktionary mp3s) or a recording feature can
be added without touching any screen. See `docs/DATA-SOURCES.md` §4 for the quality caveat.

**ADR-004 — Games are plugins, not screens.** Practice is a registry of `PracticeGame`
implementations, not a hard-coded flashcard screen. Adding game #2 must mean writing one class
and one widget and registering it. See `docs/GAMES.md`.

**ADR-005 — Scheduling lives outside games.** A `ReviewScheduler` owns "when does this card
come back". Leitner in v1, SM-2 later, swapped with one provider override and no schema change
(the SRS columns already exist).

**ADR-006 — IPA is indexed by grapheme cluster, never by code unit.** `/ˈtʃɜːrtʃ/` contains
combining marks and multi-codepoint symbols; `String.substring` will corrupt them. All
highlight ranges use `characters` grapheme offsets. This is enforced by a lint-listed helper
in `core/extensions/grapheme.dart` and covered by unit tests.

## 5. Infrastructure

- **No server, no cloud account, no cost.** Nothing to operate.
- **CI (GitHub Actions)** on push/PR: `flutter analyze` → `dart format --set-exit-if-changed`
  → `flutter test` (incl. migration tests) → build Android AAB + iOS (unsigned) as artefacts.
- **Release**: Play Console internal → closed → production; TestFlight → App Store.
  Version is `major.minor.patch+buildNumber`, build number auto-incremented in CI.
- **Signing secrets** live in GitHub Actions secrets only; never in the repo.
- **Crash reporting**: none by default (privacy + free). Instead, uncaught errors are written
  to a local rolling log the user can attach from *Settings → Help & feedback*.
- **Environment config** via `--dart-define` (`DICTIONARY_BASE_URL` (default `https://freedictionaryapi.com/api/v1`)), defaulted in code so a
  plain `flutter run` works.

## 6. Startup sequence (`bootstrap.dart`)

1. `WidgetsFlutterBinding.ensureInitialized()`
2. Resolve DB path → `getApplicationSupportDirectory()/vocabnote/vocabnote.sqlite`
   (survives app updates on both platforms; removed only on uninstall)
3. **Copy the DB to `vocabnote.pre-v<n>.bak` if a migration is pending**
4. Open Drift; run `stepByStep` migration inside a transaction
5. On migration failure → restore the backup, keep the app on the old schema, surface a
   non-destructive error screen with an *Export my data* button. **Never** delete the database.
6. Load settings → build theme → `runApp`

## 7. Testing strategy

| Level | Scope | Bar |
|---|---|---|
| Unit | schedulers, lookup-merge, grapheme ranges, backup codec | 90% on `application/` + `domain/` |
| Migration | every `vN → vN+1` and `v1 → vLatest`, with seeded data preserved | **mandatory, blocking** |
| Widget | editor, highlight editor, flashcard round | key interactions |
| Golden | word tile, word detail, flashcard — light + dark | no unreviewed diffs |
| Integration | add word → highlight → practise → export → import | one happy path per release |
